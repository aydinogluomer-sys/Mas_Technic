THE FIRST VERSION OF THIS FILE PASSED EVERYTHING, AND THAT IS RECORDED HERE
ON PURPOSE. It built the sweep on `gotoAndSettle`, which is
`domcontentloaded` + two paint frames — the right readiness contract for
layout and the wrong one for a third-party widget that mounts after
hydration. hCaptcha had not made a request yet, so the cookie jar was empty
and all six tests were green against a page that demonstrably violates the
claim. It now waits for `networkidle` (bounded, 15 s) plus 1 s per route, and
carries the positive control described above so the vacuous-pass mode cannot
return silently. This is why a gate needs a control on both sides: the
negative controls were already there and they did not catch this, because the
hollow part was the MEASUREMENT, not the comparison.

BUDGET NOTE: the two sweep tests carry `test.setTimeout(360_000)`. That is a
time budget for a 23-route walk measured at ~51 s and ~57 s, not a tolerance;
no assertion is loosened by it. The 60 s default made the first honest run
report a timeout instead of the defect.
